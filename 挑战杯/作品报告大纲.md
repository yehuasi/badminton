## 2. 作品撰写的目的和基本思路（对应申报表第 1 段）

- 背景痛点：羽毛球动作不标准却难以自查；专业教练少、贵；市面动作分析 App 多为
  云端、隐私与网络受限。
- 目的：用"单摄像头 + 端侧 AI"对普通人/初学者的击球动作做**类型识别 + 规范打分 +
  改进建议 + 回看**，把专业教练的判断标准下沉到设备端。
- 基本思路：三级流水线（粗筛 → 姿态关键点 → 识别与评分），从一开始就面向端侧部署
  设计（轻量、纯 CPU、可离线）。给一张总体架构图。

## 3. 作品的科学性、先进性及独特之处（对应申报表第 2 段；主攻先进性 40% + 科学性 20%）

### 3.1 技术关键（写出关键技术）

1. 姿态到特征的降维：YOLOv8-Pose 17 关键点 → 尺度/位置不变的 15 维动作特征。
2. 活动触发式动作切分：逐帧运动量检测挥拍起止，变长窗口重采样，快慢挥拍自适应，
   一拍只出一次结果。
3. 两阶段分组门控：先判"过顶 / 非过顶"，再在组内分类，抑制跨组误判。
4. 四项评分体系：AHP 层次分析法确定权重（动作标准度 50% / 步伐 25% / 连贯性 15% /
   动作识别 10%），识别置信度作门控。
5. 可解释评分：规则 + 关节角度区间对比，每一条建议都能追溯到具体指标与错误规则。
6. 端侧工程：显示与推理分离、ONNX Runtime 纯 CPU 部署、USB 链路访问。

### 3.2 主要技术指标（一定要有数字）

| 指标 | 数值 |
| --- | --- |
| 姿态关键点 | 17 点（COCO），不检测羽毛球，降低复杂度 |
| 端侧显示帧率 | ≈30fps（摄像头原生） |
| 端侧分析帧率 | ≈13fps（480 输入，4 线程） |
| 端侧算力 | 纯 CPU，无需 GPU/NPU |
| 识别类别 | 7 类击球 |
| 评分维度 | 4 项，百分制 |
| 模型体量 | 分类器 ONNX ≈0.36MB；姿态模型 ≈13MB |
| 基线准确率 | BFMD 公开数据跨场 ≈62%（待自采数据提升，如实写） |

### 3.3 先进性 / 创新点（对标已有方案）

- 端侧本地运行：隐私安全、无需联网，区别于云端 App。
- 可解释评分：给出可追溯的角度/错误依据，而非黑盒打分。
- 活动触发式切分：解决"一拍多次判定 / 快慢挥拍难统一"的工程难题。
- 双视角融合：正面 + 侧面分时采集融合评估。
- 完整自研链路：从数据准备、模型训练、权重论证到端侧部署全部自己完成。

### 3.4 科学性

- 技术方案合理性：三层流水线为何这样分、特征为何这样设计、权重为何用 AHP（附论证）。
- 技术意义：把"动作识别 + 质量评估"两条线解耦，符合近年可解释运动分析的研究方向。

## 4. 作品的实际应用价值和现实意义（对应申报表第 3 段；主攻现实意义 40%）

- 应用场景：体校/俱乐部教学辅助、中小学体育课、个人居家训练、健身房、康复训练。
- 经济效益：目标用户规模、单套硬件成本低（单摄像头 + 开发板）、潜在 To B/To C 模式。
- 推广价值：同一套"姿态 → 特征 → 评分"框架可迁移到其他运动（健身、网球、乒乓球），
  具备复制性。
- 成熟程度（重点写）：系统已在 SC171 v3 开发板上跑通、有实物、可现场演示，非纸面方案。
- 社会价值：普及科学健身、缓解专业教练不足、推动体育教育数字化。
